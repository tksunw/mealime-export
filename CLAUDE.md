# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

One-off tool, Mealime app shuts down soon. Two parts:

1. Share-sheet Shortcut that appends a recipe URL (`https://r.mealime.com/<id>`) to `iCloud Drive/mealime/urls.txt`. Deliberately not shipped as a binary (signed AEA archive, unreviewable, contains iCloud IDs; `*.shortcut` is gitignored). Documented in `SHORTCUT.md` (hand-build guide) and `shortcut/decoded.plist` (XML dump of the original, two iCloud IDs redacted). Keep the two in sync if the shortcut changes.
2. `mealime_export.py`: single-file, stdlib-only Python 3 script. Reads that URL list, writes markdown per recipe.

## Run

```bash
python3 mealime_export.py "$HOME/Library/Mobile Documents/com~apple~CloudDocs/mealime/urls.txt" [out_dir]
```

`out_dir` defaults to `./mealime-export`. No build, lint, or test setup exists.

## How the export works

- Each recipe page is a Next.js page. Recipe data is embedded JSON in `<script id="__NEXT_DATA__">`; the script reads `props.pageProps.publishedRecipe`. No HTML scraping beyond that regex. If Mealime changes the page shape, `extract()` is the only thing to fix.
- Output per recipe: `<slug>-<id>.md` (YAML frontmatter, Ingredients, Steps, Cookware, Nutrition) plus raw `json/<slug>-<id>.json` for fields the markdown drops, and `images/<slug>-<id>.<ext>` (from `presentation_image_url`, embedded in the markdown; skipped if already on disk).
- `nutrition` values are per serving (verified: macros reproduce `energy`). Field names used in `to_markdown()` are Mealime's own: `line_items[].quantity/ingredient_name`, `instructions[].primary_message/secondary_message` (secondary is that step's ingredient list, newline-separated `qty name` lines, not a tip), `cookwares[].name`, `serving_count`, `cooking_minutes`. Check the saved JSON before assuming a field exists.
- `fmt_nutrition()` renders flat dicts as bullets, anything nested as a JSON block.
- `app/` is the viewer web app (see `PLAN.md`). `SHORTCUT-IMPORT.md` is the hand-build guide for the Safari share-sheet Shortcut that feeds `POST /api/import`. `server.py` is a stdlib http.server: `EXPORT_DIR=<out_dir> python3 app/server.py` then http://localhost:8080. Loads `json/*.json` at startup and enriches each line item with `pantry`, `key`, `category`, each step with `uses` (split `secondary_message`). Set `CERT_DIR` (dir with `fullchain.pem`/`privkey.pem`) for HTTPS, which the wake lock and service worker need off-localhost. `static/` is vanilla HTML/JS/CSS with hash routing (`#/`, `#/recipe/<id>`, `#/cook/<id>/<step>`, `#/plan/<id>`, `#/library`, `#/staples`). Plan state (up to 5 recipe ids, last 10 plans as history, grocery checks and aisle overrides, ingredient locations and the place list, staples as `{name, category}` plus their checked names) is a JSON blob the client owns; the server only stores it at `STATE_DIR/state.json` via `GET/PUT /api/state`. Service worker is network-first except images, so deploys land on next load, plus PWA bits (`manifest.json`, `sw.js`, icons). `Dockerfile` and `docker-compose.yml` build a read-only python:3.12-slim image from the repo root context (it needs `mealime_export.py`); test with `docker build -f app/Dockerfile -t recipes .`. Note: macOS system python3 (LibreSSL 2.8) cannot serve ECDSA certs, the container can. `grocery.py` merges plan ingredients (`GET /api/grocery?ids=1,2`): sum only when normalized name and unit family match, show in the largest seen unit with amount >= 1, pantry items (no quantity) listed last with an `approx` total summed from the per-step lines; category overrides come from `state.overrides`; `scale(r, servings)` rescales a recipe's list quantities and per-step lines (nearest ⅛ for volume/mass, ¼ otherwise, unparseable strings untouched, step prose untouched) and sets `servings_base`; `GET /api/recipes/<id>?servings=N` and the grocery route (from `state.servings` `{id: n}`) both use it, the recipe header has the −/+ stepper (self-check: `python3 app/grocery.py <out_dir>`). `importer.py` adds a recipe from a URL (`POST /api/import {url, html?}`): schema.org Recipe JSON-LD to Mealime-shaped JSON plus image and markdown under `IMPORT_DIR` (default `STATE_DIR/recipes/`; the compose file sets it to `/export` so imports and the Mealime export share one tree, `/srv/recipes/data` on eyeball, rsynced nightly to tank:/ssd/recipes), loaded alongside the export with ids from 1000000 (`origin_of()` derives `origin` and `origin_url` at load: Mealime by id, URL host, "Zach Coen" when `source_url` ends in "Printer Friendly", else "File"; cards and the recipe page show it and the home filter matches it); with `ANTHROPIC_API_KEY` set one Claude call fills per-step ingredient lines, cookware and aisles. Many recipe sites 403 non-browser TLS fingerprints, so the route also accepts the page `html` fetched client-side. The same route takes `{text}`, `{pdf: base64}`, `{image: base64, media_type}` or `{file: base64}` (type sniffed by `sniff()`, what the `Add recipe file` share-sheet Shortcut sends; builder `shortcut/build_import_shortcut.py --file`), plus optional `name`: one Claude call (`from_document()`, `DOC_PROMPT`) returns the schema.org shape plus `stepIngredients` and `tool`, then `document_to_mealime()` and the same save path, with the page's printed `url` or the first link in a pasted note as `source_url`; `pdf_photo()` pulls the largest JPEG out of the PDF as the recipe image (Canva and WPRM prints keep it as DCTDecode, iOS Safari prints have none). Needs the key. `enrich()` keeps per-step lines and cookware that are already filled. `import_files.py <server> files...` bulk-posts pdf/png/jpg/txt files (self-checks: `python3 app/importer.py`). `ticktick.py` posts grocery items to a TickTick list over the Open API (`POST /api/ticktick {items}`; API key at `STATE_DIR/ticktick.json` as `access_token`, list name in `TICKTICK_LIST`, tasks go into the list's aisle columns). `ingredients.py` parses quantity strings (self-check: `python3 app/ingredients.py <out_dir>`), `categories.json` maps normalized ingredient names to grocery aisles. `GET /api/ingredients` lists every ingredient key for the `#/library` page, where each gets a house location (state `locations`/`places`); the recipe Ingredients tab can group by those. `#/staples` is the recurring-buys list: add by name (`GET /api/aisles?name=` guesses the aisle from `categories.json` plus overrides, exact key then last word; the row dropdown fixes it and persists), check items, send checked to TickTick through the same `/api/ticktick` route. Checks persist as `state.stapleChecks` (shared across devices, re-read on each visit to the tab) and clear after a successful send.
- Failures do not stop the run: failed URLs go to `<out_dir>/failed.txt`, which is valid input for a re-run.
- 1s sleep between requests, intentional. Keep it.
